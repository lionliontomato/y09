# 小音の歌單 ♬⋆

保留原 ZIP 的桌機／手機歌曲卡片與功能尺寸、歌曲卡片、搜尋、分類篩選、隨機抽歌、複製功能、版權頁。更新為淡粉紅大耳狗公主背景與 ♬⋆ 圖示。

## GitHub Pages 部署
1. 解壓縮 ZIP；將 `index.html`、`copyright.html`、`style.css`、`script.js`、`assets/` 和 `.nojekyll` **直接上傳至 GitHub Repository 根目錄**。不要把最外層資料夾一起上傳。
2. GitHub Repository → Settings → Pages → Deploy from a branch → main / (root) → Save。
3. 請確認 Google 試算表已設定「知道連結的任何人 → 檢視者」，否則網頁無法讀取。

## 試算表資料來源
https://docs.google.com/spreadsheets/d/1bJGVTmVUXbMbZoVeKUbgI8bLui6gNMSaulCZwXULSkQ/edit?usp=sharing

預設不指定 gid，改由 Google 試算表讀取第一個工作表。如果歌曲在其他分頁，請在網站網址加上 `?gid=該分頁的數字 ID`。例如 `https://你的帳號.github.io/你的專案/?gid=123456789`。請先開啟試算表的歌曲分頁，從網址中的 `gid=` 取得正確數字。

欄位格式延續原站：A 歌名、B 歌手、C 分類、D 連結（如有）、F 分類標籤；H 設定名稱、I 設定內容。分類可用逗號或頓號分隔，也有「全部歌曲」入口。網站標題會使用 H 欄「網站標題」及 I 欄對應內容，同步更新網頁大標題和瀏覽器分頁名稱；若未設定則預設為「小音の歌單」。其他標題設定維持原有讀取行為。

## 讀取失敗排查
請確認連結中的試算表 ID 無誤、權限為「知道連結的任何人 → 檢視者」，且歌曲在第一個工作表 A（歌名）、B（歌手）、C（分類）。若第一個工作表不是歌單，使用上述 `?gid=` 方式指定歌曲分頁。若 GitHub Pages 已上線，使用瀏覽器無痕視窗確認新檔案已部署。

**驗證範圍：**已執行 JavaScript 語法、封裝與資料解析的離線測試。此環境無法直接取得 Google Sheets 遠端資料，故無法替代實際公開權限與網路可用性的端到端測試。
